## 0. 一句话

低频、小批量、人工过验证、遇阻即停；不做绕过、不私信、不外传原始数据、不对外提供数据集合。

## 0.1 这份红线的依据到底有多硬（v1 新增）

v0 的数字没有写出处。核查公开资料后结论是：**两个平台都没有公布过「每天最多采多少」的阈值**，风控是多维综合判断，外部查不到可引用的数字。所以本文把每条规则标成三个依据等级，后面各节用 `[A]` `[B]` `[C]` 标注：

| 等级 | 含义 | 能否放宽 |
|---|---|---|
| **[A] 协议 / 法律** | 有明确条款或判例出处（见附录），不是数字问题，是能不能做的问题 | 不能靠调参数解决，须平台书面许可或法务意见 |
| **[B] 机制描述** | 行业公开资料对风控机制的描述（多维判断、逐级加码），**非官方、无阈值**，方向可信，具体数字不可信 | 方向不放宽；数字靠 §9 校准 |
| **[C] 团队经验值** | 起步保守取值，**没有外部依据，也没有自己的实测数据** | 只能按 §9 一次一项、有记录地放宽 |

> 实话：§1 里绝大多数数字是 [C]。它们的价值是「先保守、出事再收」，不是「已被证明安全」。  
> 唯一有实测事故支撑的是 §2（配置值 ≠ 真实拉取量）。

## 0.2 合规边界（v1 新增，[A]）

这条线比任何频率参数都重要。核查到的原文要点：

1. **小红书《用户服务协议》（2025-12-08 更新）**
   - 禁止「以任何方式（包括但不限于盗链、冗余盗取、非法抓取、模拟下载……）直接或间接盗取……用户信息等信息内容」。
   - 禁止「通过非小红书公司开发、授权、许可的第三方软件、插件、外挂、系统，登录或使用小红书平台」。
   - 「未经小红书公司书面许可，您不得复制、读取、采用、统计小红书平台的信息内容及相关数据，或者进行任何形式的销售和商业使用，或者向第三方泄露、提供或允许第三方为任何方式的使用。」
2. **抖音《企业机构账号用户服务协议》（2026-08-05 生效）§6.3**：未经书面许可，不得（1）利用平台信息宣传自身产品、为自身产品增加用户；（4）以爬虫抓取等方式使用平台信息；（7）将平台信息用于销售和商业使用或向第三方提供。抖音开放平台协议另有「不得以爬虫、拟人程序等非真实用户方式读取、转存数据」的条款。
3. **司法口径**：公开可见 ≠ 可任意采集使用。
   - 「抓取小红书用户数据牟利」案（上海知识产权法院二审，判赔 110 万元）：绕开技术保护措施获取并出售数据集合，构成不正当竞争。
   - 最高法指导性案例 262 号：未经许可获取并向公众提供数据、**实质性替代**原平台产品或服务的，构成不正当竞争。
   - 《个人信息保护法》第 27 条：可在合理范围内处理已公开的个人信息；**对个人权益有重大影响的，应取得个人同意**。昵称+评论内容可关联到具体自然人，按个人信息对待。

**据此的结论（写死）：**

- 本链路在取得平台书面许可前，**只能是内部学习验证**，不得当作商用获客的正式产能。（呼应 v0 §5 最后一条，现补上协议出处。）
- 「采集 → 打分 → 人工判断」属于内部统计分析；**把评论数据集合对外提供、出售、做成可替代原平台的内容库，一律禁止**。
- 抖音协议对「利用平台信息宣传自身产品」有明文限制：**抖音来源的线索，触达前须先过法务/书面许可确认**，不能只靠人工抽检。
- 手段合规 ≠ 目的合规：就算频率压得再低，也不改变上面几条的性质。

## 1. 频率与规模上限（硬上限，未经领航书面放宽禁止突破）

| 项 | 试跑硬上限 | 依据 | 说明 |
|----|------------|------|------|
| 并发 `MAX_CONCURRENCY_NUM` | **1** | [C]（方向 [B]） | 禁止调高 |
| 请求间隔 `CRAWLER_MAX_SLEEP_SEC` | **≥ 3s**（建议 3～5） | [C]（方向 [B]） | 禁止为提速压到 <2s。3s 是**下限**：leadctl 实际用随机间隔（对数正态，中位约 7.5s，偶尔追加 20～60s 长停顿），只会更慢；固定间隔是明显的机器特征，不建议关闭 |
| 关键词数 / 次 | **≤ 10**（v1 为 ≤3，**2026-10-02 按使用者指示放宽**） | [C] | 回退档位 3。词更多时用待采队列分批采（`collect --next`） |
| 每词笔记上限（有效） | **≤ 5** | [C] | 见 §2：配置值≠真实拉取时以真实为准 |
| 单帖一级评论 | **≤ 10**（原 ≤5，2026-10-02 放宽） | [C] | 回退档位 5 |
| 二级评论 | **关** | [C] | 默认禁止开 |
| 媒体下载 / 词云 | **关** | [C] | |
| IP 代理 | **关** | [B] | 禁止用代理绕过风控；平台风控把 IP、设备、登录环境一起看，中途换 IP 本身就是异常信号 |
| 日会话次数 | **≤ 2 次**小切片 | [C] | 两次之间冷却 ≥ 30 分钟 |
| 日笔记详情合计（估） | **≤ 50**（原 ≤30，2026-10-02 放宽） | [C]，且是估值 | 含搜索页误拉；超了当日停。回退档位 30 |
| 日评论合计（估） | **≤ 500**（原 ≤50，2026-10-02 放宽） | [C]，且是估值 | 超了当日停。回退档位 50 |

**日配额心智**：一天只验链路，不追求覆盖；宁缺样例，不赌号。

**关于「总量」和「形状」的区别（v1 补充）**：日笔记 ≤30 / 日评论 ≤50 是总量预算；关键词数、每词篇数是「总量怎么分配」的形状。同样 30 篇，可以是 3 词×10 篇，也可以是 10 词×3 篇。形状放宽不一定增加总量，但**会增加搜索请求次数**，而搜索请求对风控的影响目前没有数据，所以仍按 §9 校准，不凭推理放宽。

## 3. 遇滑块 / 验证 / 限流 —— 停手规程

风控是**逐级加码**的：先验证码、再限制功能、最后封号（[B]，多个行业来源一致）。所以前面的信号要当真，不能当成「过一下就好」。

| 现象 | 动作 | 禁止 |
|------|------|------|
| 滑块、验证码、人机 | **立刻停**（SIGTERM 进程）；保留现场给领航 | 自动点、刷、脚本过验证、找「过码」服务 |
| 登录失效 / 扫码过期 | 停；冷却后再扫 | 狂刷二维码、多开扫 |
| 429 / 频繁操作 / 空结果异常 | 停；当日不再采该号 | 换代理硬闯、降间隔重试 |
| 账号异常提示、强制改密 | **停用该号**；换隔离号或改日 | 继续采 |
| **「账号疑似存在风险」/ 功能受限（v1 新增）** | **整号停用观察 24 小时～7 天**，期间只做人工正常浏览；功能持续受限再走 App 内官方申诉 | 换设备、换 IP、反复申诉、找第三方「解封服务」 |

冷却建议：
- 单次滑块/限流后 **≥ 2 小时**（[C]）；当日第二次仍触发 → **封当天**，次日再评估。
- 出现「账号疑似存在风险」类提示：**不适用 2 小时规则**，按上表观察 ≥ 24 小时（[B]，来自行业运营资料，非官方；写保守值，观察期可以更长不可更短）。
- 官方开放平台对 API 超频返回 `30001 RATE_LIMIT_EXCEEDED`，处理建议是「降低调用频率」，不是重试。可见平台对超频的预期动作就是退让。

## 4. 账号隔离

1. **试跑号 ≠ 主号 / 商用号**；能隔离就隔离。
2. 一机一号一 Chrome 用户数据目录；禁止多账号同浏览器配置乱切。
3. **环境保持稳定（v1 新增，[B]）**：同一个号尽量固定在同一台设备、同一网络环境；IP 所在地、系统时区、浏览器语言应相互一致；不要频繁更换设备或登录地。平台是综合判断，「环境突变」本身就会抬高风险分。
4. `SAVE_LOGIN_STATE` 可开以减少重复扫码，但登录态文件 **不外传、不进 git**。
5. 封禁/强风控号：标记废弃，不用于扩量。
6. **不得为了躲风控使用指纹浏览器/多开环境（v1 明确）**：这属于规避技术措施，见 §5。

> 说明：小红书 2026-03-10 的《AI 托管运营账号治理公告》打击的是用 AI 工具完成注册、发布、互动的账号。本链路不发布、不评论、不私信，不在其直接打击范围内；但这也是「触达必须人工做」的又一理由（见 §6）。

## 5. 禁止项（零例外）

- 绕过滑块 / 风控 / 签名校验（含任何 exploit、黑产过码）
- Cookie 盗用、撞库、买号批量登
- 自动私信、加微、群发、定向骚扰
- 非公开内容、需权限才能看的数据

## 6. 数据与触达（与池栈/识需对齐）

- 原始 CSV：仅 `获客自动化/` 树内；入库前剥 `xsec_token`
- `nickname`：抽检/去重用，禁止外传原始包；对外只给脱敏版（无昵称）
- 留存：raw 30 天；excluded 14 天；ready / needs_review 暂不清
- `ready`：人工抽检 ≥30 条（或本批全量若 <30）通过后，才谈触达；触达方案另批
- **数据最小化（v1 新增，[A]）**：只保留判断意向所需字段；不采集、不推断手机号、微信号等联系方式；评论里用户自己公开的联系方式也不批量提取入库。
- **个人信息（v1 新增，[A]）**：昵称+评论按个人信息对待。触达属于「对个人权益可能有影响」的使用，**触达前须有合法依据（个人同意或其他法定事由），由法务确认**，不能以「评论是公开的」作为理由。
- **平台触达规则（v1 新增，[B]）**：小红书对站外导流管得严。笔记、评论、私信、主页里出现微信号、二维码、群号、外链、谐音/暗号引流，都可能被判违规营销并处罚。触达方案必须评估这一条，不要默认「评论区回复留联系方式」可行。
- **抖音来源线索（v1 新增，[A]）**：触达前须先确认抖音书面许可或法务意见（见 §0.2）。

## 9. 校准机制：数字怎么从「估」变成「有据」（v1 新增）

既然外部查不到阈值，就只能靠自己的记录。规则：

1. **留痕**：每次会话记录 平台、关键词数、笔记数、评论数、间隔、是否出现验证码/限流/账号提示。`leadctl` 台账（`state/runs.jsonl`）已记录会话与拦截事件，可直接汇总。
2. **一次只动一个参数**：例如这次只把词数 3→5，其余不变；同时动两个就无法归因。
3. **只在隔离小号上试**；主号、商用号不参与校准。
4. **放宽的门槛（建议值，领航可调）**：当前档位下连续多次（建议 ≥5 次、跨 ≥3 天）无任何验证码/提示，才允许申请下一档；每档幅度不超过当前值的 50%。
5. **一出信号立即回退**：任一次出现验证码/限流/账号提示，回退到上一档，并按 §3 冷却，且该参数 2 周内不再尝试放宽。
6. **放宽须领航书面确认**，并把「档位、日期、依据数据」记入变更记录。
